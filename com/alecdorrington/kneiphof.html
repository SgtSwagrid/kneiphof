trait AnyGraph[+V, +E, M]

A graph of any kind, with vertices of type V, edge labels of type E and edge multiplicities in M.

A graph of any kind, with vertices of type V, edge labels of type E and edge multiplicities in M.

Each edge value has a multiplicity, and is present exactly when its multiplicity isn't zero (see Multiplicity).

Two graphs are equal when they belong to the same family, being both directed or both undirected, with the same multiplicities, and have the same vertices and the same multiplicity for every edge. This is how Scala's collections compare within a family, so that List() == Vector() but Set() != List(). So a graph equals the hypergraph with its edges, and a lazy graph equals its materialisation, but an edgeless graph doesn't equal an edgeless directed graph or multigraph.

A graph known to have more vertices than an Int can count can only be compared with a graph built the same way, such as an equal grid, or with one known or found to have fewer vertices. Comparing it with any other graph throws an UnsupportedOperationException, since that would mean listing more vertices than a set can hold. Such graphs hash only their order, so they can be kept in hash sets and maps, alongside graphs built the same way.

trait Chain[+V, +E, +L] extends GraphBase[V, E | L, Count]

A multigraph built by chaining edges, as in 1 ~ 2 ~ 3, which holds the edges 1 ~ 2 and 2 ~ 3.

A multigraph built by chaining edges, as in 1 ~ 2 ~ 3, which holds the edges 1 ~ 2 and 2 ~ 3.

As a multigraph, a chain only records its edges and how many times each occurs, so 1 ~ 2 ~ 3 == 3 ~ 2 ~ 1. It also remembers where it was last extended, its tip, so that it can be extended again. Equality compares only the graphs, so equal chains can continue from different tips: 1 ~ 2 == 2 ~ 1, but (1 ~ 2) ~ 3 adds 2 ~ 3, while (2 ~ 1) ~ 3 adds 1 ~ 3. Every Edge is a chain of one edge.

sealed trait Embedding[N, M]

Evidence that multiplicities in N can be read as multiplicities in M, preserving sums.

Evidence that multiplicities in N can be read as multiplicities in M, preserving sums.

Every multiplicity embeds in itself, and counts embed in every multiplicity as repeated sums of one. This is what lets edges and chains, which are multigraphs, be added to graphs of any kind, as in g + (1 ~ 2).

There are no others, so edge sets don't embed in multigraphs: reading each edge as one copy doesn't preserve sums. Use HypergraphBase.counted or DirectedHypergraphBase.counted to read an edge set as a multigraph explicitly.

trait Handle

A handle on a vertex or edge of a graph, such as g(1), from which its neighbourhood can be explored.

A handle on a vertex or edge of a graph, such as g(1), from which its neighbourhood can be explored.

A handle stands for its value, but isn't it. Queries and updates such as AnyGraph.hasVertex, GraphOps.induced and GraphOps.addVertex take vertex and edge values, and reject handles at compile time (see NotHandle), since a handle would never be found as a vertex or edge. trait Multiplicity[M] extends Semiring[M], Lattice[M]

A typeclass for edge multiplicities, i.e. how many times a graph contains each edge.

A typeclass for edge multiplicities, i.e. how many times a graph contains each edge.

A graph assigns each edge value a multiplicity, where zero means that the edge is absent. Every graph operation is defined once in terms of this algebra:

  • Sum (+) adds multiplicities.
  • Union (|) and intersection (&) take their join and meet.
  • Difference (-) subtracts them, stopping at zero.

With Boolean this gives graphs whose edges form a set, and with Count it gives multigraphs.

Attributes

Note

Laws, in addition to those inherited:

  • Order: x | y == y if and only if x + z == y for some z.
  • Bottom: zero | x == x.
  • Monus: x - y is the least z such that x | (y + z) == y + z.
  • Count: zero.count == 0 and one.count == 1.
  • Additivity: if additive, then (x + y).count == x.count + y.count.

final class NotGraph[F]

Evidence that F isn't a graph, or an edge (which is a graph), so that it can label an edge with % or Chain.withLabel.

Evidence that F isn't a graph, or an edge (which is a graph), so that it can label an edge with % or Chain.withLabel.

This catches a mistake of precedence: % binds more loosely than ~, so 1 ~ 2 % "a" ~ 3 means (1 ~ 2) % ("a" ~ 3), which would label 1 ~ 2 with the edge "a" ~ 3. An edge can still be labelled by a graph through its constructor, as in Edge(1, 2, graph).

trait Shapes[+G[v, e]]

Constructors for common shapes of unlabelled graph, of kind G.

Constructors for common shapes of unlabelled graph, of kind G.

A shape's edges are never stored: queries such as AnyGraph.hasEdge, AnyGraph.size and vertex degrees are answered from the shape, and the edges are only computed if something needs all of them, such as iterating over them.

Each shape can be built on the vertices 0, 1, ..., given how many there are, as in path(3). Shapes whose vertices come in a single sequence can also be built on the given distinct vertices, as in path("A", "B", "C"). Complete graphs are the exception, with complete taking sizes and clique taking vertices, so that clique(3) can't be mistaken for complete(3).

final class ValueMap[+K, +A] extends Iterable[(K, A)]

An immutable map from keys of type K, compared only by equality, to values of type A.

An immutable map from keys of type K, compared only by equality, to values of type A.

Unlike Map, a value map is covariant in its keys, so a ValueMap[Int, A] is also a ValueMap[Any, A]. Lookups accept any key for the same reason. It's stored as a hash trie, so lookups and updates take effectively constant time.

type NotHandle[A] = Lookup[A, Any]

Evidence that A isn't a Handle, so that it can be looked up as a vertex or edge value, or become a vertex (see Lookup).

Evidence that A isn't a Handle, so that it can be looked up as a vertex or edge value, or become a vertex (see Lookup).

This catches a mistake that would otherwise fail silently: a handle such as g(1) is never itself a vertex, so g.hasVertex(g(1)) would be false, and g.removeVertices(g(1).neighbours) would remove nothing. Every method which looks up a vertex or edge, or adds vertices, requires it, so handles don't become vertices either. Only the type of a value is checked, so a handle can still become a vertex as an Any, in a collection whose elements are only known to be Any, or through an edge's own constructor, such as Edge(a, b).
